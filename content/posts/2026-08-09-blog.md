블로그 빌드 과정에서 발행 글이 누락되던 시각 오차 문제를 해결하고, 네이버 서치어드바이저 소유확인 방식을 메타태그에서 파일 직접 제공 방식으로 바꿨다. 아울러 Play Console API 연동 중 발생했던 403 대응 기록 원고를 새로 추가하고 유입 개선을 위한 레이아웃을 고쳤다.

## 미래 시각으로 찍힌 글이 정적 생성에서 누락되었다

글을 분명히 올려두었는데도 빌드 결과물에 포함되지 않는 현상이 나타났다. 정적 사이트 생성기인 Hugo는 글의 작성 시각이 현재 시각보다 나중으로 설정되어 있으면 이를 미래 게시물로 판단하여 결과물 생성을 걸러낸다. 포스트 파일의 타임스탬프가 작성 시점보다 앞서게 잡혀 있었기에 빌드 엔진이 해당 글들을 건너뛰었던 것이다. 발행 일시를 시스템의 현재 시각으로 고쳐 써서 엔진이 정상적으로 인식하도록 수정했다. 빌드 파이프라인의 예약 발행 기능에 의존하는 대신 즉시 노출되도록 타임스탬프 정확도를 확보한 셈이다. 이제 새로 올린 원고들이 빌드 시점에 즉시 파싱되어 웹사이트에 빠짐없이 올라간다.

## 메타태그 검증이 실패하여 전용 파일 업로드로 전환했다

네이버 서치어드바이저에 사이트를 등록하는 과정에서 hugo.toml 파일에 메타태그를 삽입하는 방식을 시도했으나 소유확인 검증을 통과하지 못했다. 템플릿 헤더 구조상 태그 파싱 시점이나 수집 로봇의 스크랩 조건과 맞지 않아 인식이 되지 않는 상황이었다. 이를 해결하기 위해 정적 자원 디렉터리인 static 밑에 인증용 HTML 파일을 직접 배치하는 구조로 변경했다. 메타태그 설정 한 줄보다 관리 대상 파일 하나가 새로 늘어났지만 수집 로봇의 경로 접근 확실성을 얻었다. 루트 경로에 파일이 직접 노출되면서 소유권 확인 절차가 지체 없이 처리된다.

## Play Console 업로드 오류 기록 추가와 하단 유입 레이아웃을 개선했다

Play Console AAB 업로드 자동화를 진행하면서 Developer API 설정과 403 권한 오류를 다룬 포스트를 새로 작성했다. 권한 미비로 발생하는 403 응답 문제와 그 해결 과정을 글로 정리하여 수록했다. 이와 동시에 방문자의 유입 경로와 하단 레이아웃을 보완하기 위해 extend_post_content 템플릿 구조를 손보았다. 원고 분량이 늘어난 대신 콘솔 API 연동 시 겪는 권한 문제의 해결 절차를 명확하게 남겼다. 글 하단의 연관 안내 영역이 제대로 표시되어 방문자가 필요한 정보를 곧바로 이어서 읽을 수 있게 되었다.

포스트의 발행 시각 누락과 소유확인 문제는 정돈되었으나, 새로 작성된 API 연동 글이 실제 검색 엔진 수집 로봇에 의해 색인되기까지는 시간이 더 걸릴 것으로 보인다.
