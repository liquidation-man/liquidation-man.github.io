## 오늘의 요약 3줄

- 매일의 작업 내역을 자동으로 글로 남기는 **무인 블로그 파이프라인**을 만들기 시작했다.
- 발행 채널은 **Hugo + PaperMod + GitHub Pages** — 로그인도 캡차도 없이 `git push` 한 번으로 배포가 끝난다.
- 수집 → 생성 → 발행을 모듈로 나누고, 발행 대상은 인터페이스로 추상화해 나중에 다른 블로그도 끼울 수 있게 설계했다.

## 왜 이걸 만드는가

여러 사이드 프로젝트를 동시에 굴리다 보면, 정작 "오늘 뭘 했더라"가 흐릿해진다. 커밋 로그는 남지만 **왜 그렇게 했는지**는 며칠만 지나도 사라진다. 그래서 매일의 작업을 자동으로 기록하고, 이왕이면 검색으로 찾아올 사람에게도 쓸모 있는 글로 남기기로 했다.

핵심 제약은 하나였다. **사람이 개입하면 안 된다.** 매일 밤 자동으로 돌아 글이 올라가야 한다.

## 왜 Hugo + GitHub Pages인가

후보는 티스토리, 네이버 블로그, 워드프레스, 그리고 정적 사이트였다. 무인 자동화라는 조건에서 정답은 명확했다.

- **로그인·캡차가 없다.** 티스토리·네이버는 브라우저 자동화로 로그인 세션을 유지해야 하고, 캡차나 정책 변경에 취약하다. 정적 사이트는 `git push` 만 하면 된다.
- **무료다.** GitHub Pages는 호스팅 비용이 0원이다.
- **SEO·모바일 기본기가 좋다.** PaperMod 테마는 반응형·다크모드·사이트맵·RSS를 기본 제공해, 검색 유입과 광고 수익화에 유리하다.

다만 특정 플랫폼에 종속되긴 싫어서, **발행 계층은 인터페이스로 추상화**했다. 지금은 GitHub Pages 어댑터 하나뿐이지만, 나중에 티스토리·네이버 어댑터를 브라우저 자동화 방식으로 끼워 넣을 수 있다.

## 전체 구조

```text
Collector  →  Writer  →  Publisher  →  Scheduler
 (수집)       (글 생성)     (배포)        (매일 실행)
```

- **Collector**: 로컬 git 저장소들을 순회해 지난 24시간의 커밋·변경 파일·통계·주요 diff를 모으고, 작업 세션 기록에서 "왜/어떻게"의 맥락을 보강한다. 이 단계에서 민감정보를 전부 마스킹한다.
- **Writer**: 수집 데이터를 프롬프트 템플릿에 넣어 한국어 개발일지 글과 SEO 메타데이터를 생성한다.
- **Publisher**: 마크다운을 커밋·푸시하면 GitHub Actions가 Hugo로 빌드·배포한다.
- **Scheduler**: OS 스케줄러에 매일 실행을 등록하고, 상태 파일로 중복 발행을 막는다.

## 배운 점

정적 사이트 생성기를 "블로그 도구"가 아니라 **배포 API**로 보면 자동화가 단순해진다. 글을 파일로 떨어뜨리고 push하는 순간 나머지는 CI가 알아서 한다. 사람이 볼 화면(에디터, 관리자 페이지)이 파이프라인에는 오히려 걸림돌이라는 걸 다시 확인했다.
